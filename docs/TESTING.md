# SBC-Context-Router: End-to-End Testing and Verification Guide

This document provides a comprehensive, sequential checklist for testing your Asterisk dialplan, verifying database persistence, and running the C# .NET Core FastAGI sidecar proxy daemon in a production or testing environment.

---

## Step 1: Initialize and Test the SQLite Routing Database
Before starting the sidecar daemon, verify that your SQLite database initializes correctly and can handle rapid read/write operations for the context cache.

1. **Verify Database Creation:** Start the C# application or check your working directory to ensure `routing_cache.db` is successfully generated by `ContextResolver.cs`.
2. **Insert Test Records:** Verify that your lookup table contains test numbers mapped to appropriate account IDs and routing profiles:
   ```Bash
   SELECT * FROM ContextCache WHERE PhoneNumber = '+17171234567';

## Step 2: Deploy and Start the C# Sidecar Daemon
The C# service acts as an asynchronous FastAGI proxy listening on loopback port 4573 to handle high-concurrency requests without blocking Asterisk worker threads.
     
1. **Publish the Linux Binary:**
On your development machine, compile the standalone executable:
   ````Bash
   dotnet publish -c Release -r linux-x64 --self-contained true -o /var/lib/sbc-context-router/bin
2. **Start the Service:**
Ensure the systemd service is active and running:
   ```Bash
   sudo systemctl start sbc-context-router.service

**Verification:** Confirm that the FastAGI server is actively listening on the loopback interface:
   ````Bash
   sudo ss -tulpn | grep 4573
   ````
You should see 127.0.0.1:4573 in the listening sockets output.

## Step 3: Reload Asterisk Configuration Files
Apply your updated PJSIP and dialplan rules without restarting the Asterisk service.
1. **Reload Modules:**
   Execute the core reload command in the Asterisk CLI:
   ````Bash
   asterisk -rx "core reload"

**Verification:** Run asterisk -rx "pjsip show endpoints" and confirm that source_pbx and external_voice_agent are loaded successfully and report zero registration errors.

## Step 4: Test Dialplan Pattern Matching & Database Escalation Memory
Verify that incoming calls from your source PBX correctly match your prefix/suffix or 10/11-digit rules and write campaign context keys into Asterisk's internal database (astdb).

1. **Simulate a Pattern Match Test Call:**
Use Asterisk's internal application testing tool to simulate a call matching your prefix pattern:
   ````Bash
   asterisk -rx "dialplan test application Dial PJSIP/_DEPT1_1234@source_pbx"

**Verification:** Inspect the internal database to ensure the CallerID and queue ID have been successfully stored:
   ````Bash
   asterisk -rx "database show escalation"
   ````

Run asterisk -rx "pjsip show endpoints" and confirm that source_pbx and external_voice_agent are loaded successfully and report zero registration errors.

## Step 5: Test the Escalation Context Retrieval Flow
Verify that when a call returns to the escalate extension from the voice agent, the system retrieves the original context from memory, routes it back to the source PBX, and cleans up the database record.

1. **Simulate an Escalation Call:**
Trigger a test escalation event via the CLI:
   ````Bash
   asterisk -rx "channel originate Local/escalate@from-external-agent application NoOp test"

**Verification:** Inspect your live logs (tail -f /var/log/asterisk/messages) to confirm that TARGET_DEST successfully retrieves the correct queue ID from memory and executes DB_DELETE to free up database space.

## Step 6: End-to-End System Integration Test
Perform a live call simulation through your complete pipeline:

1. An incoming call hits source_pbx.
2. The dialplan triggers the C# FastAGI sidecar (127.0.0.1:4573), which executes a time-boxed 5ms lookup and returns variables (CACHED_ACCOUNT_ID, CONTEXT_STATUS).
3. Asterisk injects custom headers (X-Enterprise-Context) and bridges the call to the external voice agent.
4. Upon return, context is retrieved via the escalate context and routed back to the correct campaign queue.

**Verification:** Monitor live system performance and logs using journalctl and Asterisk verbosity:
   ````Bash
   sudo journalctl -u sbc-context-router.service -f
   asterisk -rx "core set verbose 3"
   ````
